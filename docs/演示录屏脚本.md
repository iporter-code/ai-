# 演示录屏脚本与制作方式

成片：`docs/演示录屏.mp4`，**3:21**（201 秒），1920×1080 / 30 fps / H.264，5.6 MB，随仓库提供。
22MB 的旧版录屏已弃用；新片基于当前代码（3 文档 / 32 片段 / 33 项测试）重新录制。

## 怎么做的

不是手工剪辑，而是两条脚本串起来，保证「画面里的每个字都来自真实运行」：

```bash
# 1. 真实跑 5 道题（含 2 道陷阱题），记录逐字时间戳、首 token、总耗时、Top-4 分数
python scripts/record_demo.py          # → docs/demo_run.json、docs/demo_run.log

# 2. 按日志渲染成终端回放视频（命令逐字敲出，等待时长用实测值）
python scripts/build_demo_video.py     # → docs/演示录屏.mp4
```

`record_demo.py` 直接调用 `app.rag.answer_question`，与 CLI 走同一条代码路径；
`on_delta` 回调记录每个字符的到达时刻，所以「首字 7.79s」这类数字不是写死的。
画面页脚常驻「真实运行回放 + 录制时间 + 模型」，不冒充实时屏幕录制。

每道题画面里都会打出「首字 / 总耗时 / 检索方式」和 Top-4 分数，分数就是本次运行的真实输出。

## 复现

```bash
python -m app.cli ingest                  # 先建索引（3 文档 → 32 片段）
python scripts/record_demo.py             # 重录问答（免费接口有 30s 限流，默认等 32s）
python scripts/build_demo_video.py        # 重新出片，约 3 分钟
```

若换了付费或本地模型，`record_demo.py --sleep 0` 可去掉限速等待。
两条脚本都只读索引、只写 `docs/` 下的产物，不改动任何评测结果。

## 说明

- 视频不含 API Key、`.env` 内容或私人文件；`info` 只显示「Key 已配置」。
- 陷阱题已在 `eval/questions.jsonl` 与检索结果中双重确认：语料里没有 Chroma 版本号，也没有莫干山内容。
- 本机 ffmpeg 的文件读写被安全策略拦截（只能走管道），因此视频是**分片 MP4**（`ftyp→moov→moof→mdat`）。
  时长字段已由 `build_demo_video.py` 回填为 201.3 秒，VLC / 浏览器 / Windows 媒体播放器均可播放；
  若个别老播放器显示异常，用 VLC 或任意转码工具重新封装一次即可。

# 我的 RAG 实验日记

> 从零搭个人知识库问答助手的全过程记录。所有数字都是我在自己电脑（i5-12400，16G 内存，无显卡）上实测的。

## 2026-10-12 周一：跑通最小链路

今天把最小链路跑通了：读入 4 篇文档 → 切分 → 检索 → 拼提示词 → 调 DeepSeek API 生成。第一次提问"幻觉分哪两类"，系统答对了，但把"忠实性幻觉"说成了"忠诚度幻觉"，明明是照着检索结果抄还能抄错字，挺无语的。后来在提示词里加了一句"请使用材料中的原词"，问题消失。

第一次实测延迟：DeepSeek API 首 token 大概 1.8 秒，整段回答 4 秒左右。检索本身只要几毫秒，瓶颈全在生成。

## 2026-10-13 周二：chunk 切分长度实验

用我写的 8 道测试题，分别按 200 字、300 字、500 字切分，看 Top-3 检索命中率：

- 200 字切分：命中率 5/8。问题是有些段落被从中间砍断，"BM25 的两个参数 k1 和 b 分别是多少"这种题，k1 在一个 chunk、b 在另一个 chunk，答案直接断成两截。
- 300 字切分：命中率 7/8，最好。
- 500 字切分：命中率 6/8。段落完整了，但噪声变多，不相关内容会稀释相似度。

结论：**中文笔记类文档按 300 字左右切分、相邻段重叠 50 字**是比较稳的配置。重叠很重要，可以防止关键句恰好落在边界上被切断。

## 2026-10-14 周三：BM25 vs 向量检索对比

同样 8 道题各跑一遍（Top-3）：

- BM25 命中 6/8，丢的两道都是同义词问题："电脑跑不快怎么办"检索不到"Python 性能优化"。
- 向量检索（bge-small-zh）命中 7/8，丢的一道是"pip install 报错 Microsoft Visual C++ 14.0 怎么办"，因为向量模型把"14.0"这种版本号当成噪声。

**专有名词和版本号找 BM25，口语化提问找向量**，和周老师课上说的一模一样。纸上得来终觉浅。

## 2026-10-15 周四：踩了一个大坑——幻觉拒答

今天测试陷阱题。问系统"Transformer 论文《Attention Is All You Need》发表于哪一年"，我的语料里根本没写这个。结果系统脸不红心不跳地回答"2017 年"——这是模型自己脑子里的知识，不是我文档里的。

这就是忠实性幻觉的经典表现：**检索环节什么都没查到，生成环节却假装查到了**。

修复办法：加一个"检索置信度门槛"。BM25 得分低于 2.0、或向量余弦相似度低于 0.25 时，直接回复"文档中没有相关信息"，根本不给模型自由发挥的机会。改完之后 3 道陷阱题全部正确拒答。

教训：**提示词里的"不许编"是君子协定，代码里的硬门槛才是防盗门。**

## 2026-10-16 周五：bge-small-zh 首次加载太慢

第一次跑向量检索时，bge-small-zh 模型下载加加载花了 6 分钟，我以为程序卡死了差点强退。后来发现模型会缓存到 `~/.cache/huggingface`，第二次启动只要 3 秒。

另外 bge 系列官方建议在**查询句**前面加指令前缀"为这个句子生成表示以用于检索相关文章："，文档句不加。我实测加不加前缀对命中率影响：加前缀 7/8，不加 6/8，有提升但不夸张。国内网络下载模型记得设 `HF_ENDPOINT=https://hf-mirror.com` 走镜像。

## 2026-10-17 周六：引用来源怎么标

老师要求答案末尾必须注明出处（文档名 + 原文片段）。我的做法是：检索结果里每个 chunk 本来就带着 `doc_name` 和 `chunk_id` 元数据，生成时把编好号的材料（[1] [2] [3]）塞进提示词，要求模型在答案末尾用同样的编号列出引用，最后程序把编号翻译回文档名。

试下来模型偶尔会引用不存在的编号，比如材料只有 3 段它写 [4]。程序里加了一行校验：引用编号超出范围就丢弃该条引用。**凡是模型输出的结构化内容，都要过一道程序校验**，这是我这周悟出的最重要的工程习惯。
